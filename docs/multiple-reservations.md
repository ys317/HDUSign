# 多门课程预约（v2.2.0）

- 点击课程只切换查看，不添加、取消或替换预约，也不改变正在监听的链接。
- 每个账号可以预约多门课程，按开课时间排序，使用原有每节提前两分钟、最后下课延后两分钟的时间规则。
- 每个账号仍只有一个监听任务，按时间依次启动；本次按用户确认的课程不重叠情形设计。
- 课程列表标记“已预约”或“监听中”。详情页的“本账号预约”列出全部预约，可分别查看、取消。
- 监听中可以查看和预约其他未开课课程；点击“正在监听”提示可回到正在运行的课程。
- 转写、签到码、活动记录和已运行时间归属启动时的课程。查看其他课程不会把这些内容显示为另一门的记录。
- 到点启动的任务固定使用该预约的 URL、连堂课元数据及机器人课程名称，不使用当前正在查看的 URL。
- 配置中的 `scheduled_course` 自动迁移为 `scheduled_courses` 列表。写入失败不改变内存中的预约队列。
- 启动时只移除该门已启动课程的预约，其余保留。取消仅删除指定课程。软件关闭期间不能监听；未过期预约在重启后恢复。
- 账号文件仍单独保存在各自 `account_data` 目录中。五个账号的同时监听上限保持不变。

验证：`test_multiple_reservations` 覆盖多门保存恢复、旧格式迁移、浏览不取消、定时启动 URL 与通知名称快照、两门顺序启动、运行中浏览及预订、转写与日志隔离、写入失败回滚、账号队列隔离及实际 QML 操作。所有测试使用临时账号及模拟服务，不提交真实签到或机器人通知。
