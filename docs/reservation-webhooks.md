## 当前判断方式

每门课程仍单独保存 `reservation_webhooks` 绑定（课程 URL、机器人名称、端点指纹、DPAPI 加密链接），所有账号共同检查。

比较区间为 `[课程开始 - 120 秒, 课程结束 + 120 秒)`；两个区间的起点都早于对方终点时才冲突。边界恰好相接不冲突。连堂课的开始／结束取首节和末节，课间属于同一监听区间。十分钟正式课间扣除两侧各两分钟后还剩六分钟，可以复用。

同一实际企业微信机器人按 Webhook 的 `key` 指纹识别；名称、参数顺序和额外参数不改变身份。未知或无效课程时间不能证明不重叠，因此不自动复用。当前判断只覆盖本软件实例载入的账号，不查询微信端或其他电脑的使用情况。

预约成功即保存该门课的时间绑定。机器人可同时绑定多门不冲突的预约，取消、过期或结束一门只解除该门的占用。修改默认机器人不影响已有预约；已绑定预约换机器人仍需先取消再预约。

## 启动与人工选择

冲突弹窗显示账号、课程和时间，仅列已测试且与本课程不冲突的机器人。点击确认重新检查。没有可选项时，添加并测试机器人，或取消本次操作；不自动换到另一机器人。

启动时再次检查，提前手动启动按实际开始时间扩展区间。正在结束或超出计划结束仍未退出的任务，须等进程及推送结束才解除保护。到点的已有预约若遇冲突，继续本地识别和记录，暂停微信并提示选择，不能与旧任务同时推送。监听中为待处理任务选定机器人时，使用其实际运行区间复核；只推送新提醒，不补发旧记录。

旧预约及重启恢复使用相同时间规则；冲突、绑定损坏或解密失败时标记“待选择机器人”，不退回账号默认机器人。

## 通知隔离与验证

每个任务保留独立加密的 `notification_routes/<随机标识>.json`。工作进程只接受当前账号目录和正确任务标识；文件缺失、损坏或不符时关闭推送。姓名、课程与任务快照绑定。当前源码只推送识别提醒和签到码，不再执行自动签到或发送签到结果／验证码通知。

`test_reservation_webhooks` 覆盖：跨账号与同账号不重叠复用、十分钟课间、恰好四分钟课间、一秒重叠、连堂课、取消单门、重启恢复、提前启动、未知时间、旧进程结束保护、确认时复查、保存失败回滚、别名、真实 QML 及模拟 HTTP 目标。`test_notification_only` 验证旧配置开启自动签到时仍只产生微信签到码通知，以及旧命令入口被拒绝、设置清理。

测试使用临时账号、虚拟时钟和模拟请求，没有真实签到、学校登录或机器人推送。真实课堂、真实微信投递尚未验收；v2.3.2 新 EXE 的离线验收见下。

2026-10-22 验证记录：当前 Qt 主界面及相关模块共 385 项，380 项通过、5 项本地 FFmpeg 集成测试因运行环境无通用 FFmpeg 而跳过；最后针对机器人、提醒和 QML 的 44 项全部通过。日志在 `build/notification-current-regression.txt` 和 `build/notification-final-targeted.txt`。

补充验证限制：尝试使用随程序提供的音频专用 FFmpeg 运行上述 5 项通用 FFmpeg 测试，结果为 2 失败、3 错误（包含造数所需 lavfi／编码能力缺失及协议错误分类差异）；这批额外测试没有通过，未调整音频组件。历史 Tk 测试在便携 Python 缺少 tkinter；另用 Python 3.12 补充测试时，完整界面被既有 CustomTkinter 滚动条 API 不兼容及 Qt 依赖缺失阻断。当前生产 Qt 的 QML 测试正常通过，不能将结果表述为整个历史测试集全部通过。

2026-10-23 v2.3.2 交付验证：源码回归 388 项（383 通过、5 跳过）；新增构建测试覆盖模块更新、删除旧模块及名称／版本资源。新 EXE 的 Qt 主题渲染、非重叠机器人复用、重叠冲突、ASR、语义模型、音频专用 FFmpeg 编解码、浏览器与登录检测自检全部通过；另以五个冻结进程验证通知路由隔离。真实学校请求及真实机器人推送均为零。
