# 使用指南


## 课堂与账号

打开软件后，进入「设置」，输入本人学号和密码，点击「登录并读取课程」。软件自动填写登录表单，验证码等验证仍由本人完成。登录成功后选择课程，点击「开始监控」或「预约直播」即可，账号、课程和设置会自动保存。

桌面界面统一使用后台直播音频：当前课程点击“开始监控”，未来课程点击“预约直播”，软件直接接收声音，无需保持网页播放，也不会从扬声器播放课程。旧配置如果关闭了后台音频，进入多账号界面后会启用当前界面所需的直播模式。

命令行仍保留电脑声音采集；这是独立入口，使用方式见[开发指南](development.md)，不在多账号界面中切换。

已有直播登录时，打开软件会自动读取课程，也可以点击「刷新课程」。刷新只更新列表，需本人选择课程；不会自动选中另一堂课。手动输入可在「设置」中通过「手动填写网址」展开。列表为空或读取失败时，页面显示原因并保留已有手动地址，登录过期请重新登录。

课程列表保留今天与明天的课程，并显示起止时间。课程未到监听时间时可预约，到点启动；有课表的课程提前两分钟尝试。每账号可预约多门不重叠课程，依次监听；选择其他课程只改变查看内容，不取消已有预约。预约列表可分别查看、取消，重启后恢复未过期预约。配置按账号保存，关闭或睡眠期间无法采集。

正文以课程名作为页面标题，主操作按钮位于标题旁；切到设置或向下滚动时仍能停止当前任务。账号任务栏可切换查看其他账号，不会停止它们的监听。课程加载失败时显示原因并提供重试入口；只有成功读取且没有课程时才显示“今明暂无直播课程”。

预约到点后使用该课程保存的地址、课表和通知绑定启动，不会误用正在查看的另一门课。开启自动签到时同时准备该账号的签到页。平台未开播时每六秒尝试，最多等待到对应节正式开始后两分钟；登录失效或无权限会提示处理。单账号同一时间只监听一门课程。

后台音频适合只需要转写和提醒、希望减少网页和视频占用的情况。目前支持杭电平台的 HTTP(S)-FLV 直播；直播尚未开始、已经结束或格式不支持时，会显示原因。请在平台支持的直播时间内重试；桌面界面没有电脑声音模式。短暂断流会自动重连，持续失败约两分钟后停止并提示；恢复稳定接收后，下一次断流可重新尝试。网络补发或电脑短暂繁忙造成的音频积压会先缓冲再追赶；积压超过约 10 秒时跳过积压部分并在记录中提示，监控继续进行。更换直播链接后需要重新启动监控。直播源同时包含画面时，网络流量未必明显下降。

重连期间显示“正在重连”，收到声音后恢复“监控中”。登录过期、无权限、证书或组件问题会提示处理；停止可取消重连等待。核验后的两节连堂复用首节链接，三节连堂在第三节课前两分钟切换到已确认的第三节链接；切换会清除未完成转写，避免把两段数字拼成签到码。详情见[连堂课](continuous-lessons.md)。

需要其他账号时，在设置中选择已有账号或点击“新账号”。成功登录且勾选记住后保存加密密码；取消记住不会自动删除已有记录。每个账号独立读取课程、保存预约和登录态，最多同时监听五个账号；切换查看不停止其他任务。删除账号须先停止该账号任务，并确认清除其数据。外部浏览器切换账号不会同步到软件。详见[账号管理](accounts.md)与[多账号](multi-account.md)。

签到辅助共用设置中填写的账号，启用「自动签到」后，启动监控会自动登录并准备签到页；若需提前验证，可在「设置」点击「重新登录签到」。签到会话按账号分别保存，升级后的首次使用可能需要重新验证。

签到位置在「设置」页。点击「获取当前位置」可通过 Windows 系统定位填入经纬度，显示的误差范围由系统提供；核对后点击「保存」，也可以手动填写。定位需要在 Windows「设置 → 隐私和安全性 → 位置」（Windows 10 为「设置 → 隐私 → 位置」）中开启位置服务并允许桌面应用访问位置。未开启、权限不足或定位超时时，软件会显示原因，保留原有坐标。

初始默认值为纬度 `30.314732`、经度 `120.343727`，这不是自动测得的当前位置。已有个人设置仍会保留。签到使用已保存的经纬度，请在启动监控前核对；获取位置只在点击按钮时进行，返回的是经纬度，不含街道门牌地址。

只需转写与提醒时，在设置中关闭「自动签到」，可跳过签到登录。后台音频仍需要取得课程的观看权限；直播登录与签到登录分别保存，互不覆盖。

## 转写与签到码

点击“开始监控”后，软件初始化本地模型并接收声音；后台音频模式会先确认直播可用。实时转写、签到码与活动记录归属实际运行课程，查看其他课程不会更改归属。活动记录默认折叠，展开或折叠不影响识别和磁盘日志。

点击「停止监控」会清空待处理的签到任务，并停止正在运行的签到浏览器；清理完成后可再次启动监控。监控期间关闭窗口也会等待清理完成。已提交到平台的签到请求无法撤回，请以平台记录为准。

确认后的四位签到码会显示在卡片上，点击「复制」即可粘贴到课堂页面。同一堂课可以识别多个不同的签到码。重新启动监控会清除上次的签到码，避免误用；「清空」只清理活动记录的显示，保留当前签到码和计时。

默认支持提前提码：同一码在连续识别中保持稳定，四位数字后已经出现后续话语，或者已经完整重复读出两遍，就可以在整句话结束前显示、通知和签到。刚出现四位数字时还可能继续增长为长数字串，因此先等候确认；不满足提前确认条件时，仍使用整句完成后的结果。

启用「自动签到」后，启动监控时就会在后台任务中打开签到浏览器并准备签到页，不必等待口播提示；页面准备与音频初始化同时进行，确认码后才输入并提交。同一次监控复用浏览器，每轮结束后准备空白键盘，供下一轮签到使用。页面准备失败不阻塞转写，确认码后会再尝试打开。关闭自动签到时不会预开页面；若旧配置显式设置了 `auto_sign.prewarm_browser: false`，改为 `true` 可启用启动时预开。实际等待仍受登录状态和学校网络影响。

点击“签到”后若出现阿里云的点击式验证，软件会在已识别的区域中对明确按钮或未勾选复选框尝试点击一次，然后等待平台确认。按钮无法识别、点击后仍需操作或出现滑块、图片点选时，会切到签到浏览器并提示“签到等待验证”，请在页面手动完成。验证组件消失或按钮点击成功不等于签到成功，仍需收到平台本次签到的成功响应。

`auto_sign.captcha_trajectory` 控制本地轨迹增强，默认开启。启用后，等待签到码期间可做缓慢指针移动，输入与提交使用连续移动；自动验证点击允许一次、短时间内的行为替换，未发生人工操作的空白静默轮也可使用扰动样本。关闭开关会同时关闭轨迹替换、巡游、移动和随机按键停顿。处理失败时保留原请求，自动点击失败、等待人工处理或观察到人工操作后停止本轮注入。

轨迹样本保存在当前账号目录的 `trajectory_library.json`，最多保留 40 份并去重；普通单账号入口使用程序数据目录。只有观察到人工输入、没有混入自动输入、且本次签到获得明确成功响应后，才把暂存样本加入库。自动巡游与按键轨迹不会作为真人样本保存。扰动保持事件时间顺序，坐标围绕实际点击终点缩放到视口内，并保留当前会话的 userAgent 与 clientType。离线回归验证这些边界，不保证学校风控通过率；本地研究资料见 `captcha-research/notes/03-trajectory-replay-experiment.md`。

只有检测到可见的验证组件或接口明确返回验证要求时，才会提示「签到等待验证」；页面没有验证码时不会因为等待超时而误报验证码。

等待期间不会自动刷新页面或重复点击签到，转写继续运行；同一码在当前任务处理或排队期间重复出现，会合并到已有任务。提交后的等待上限为 120 秒，同时受 `auto_sign.timeout_seconds` 的任务总时限约束（默认 180 秒，允许 30–1800 秒；非法值回退到默认值）；超时后结果显示为未知，请到平台核对。点击「停止监控」可随时取消等待。控制台和通知会默认隐藏四位签到码，临时结果文件仍只用于当前任务的内部匹配；只有排查本机问题时才临时设置 `ECHOSIGN_DEBUG_SIGN_INPUT=1`，结束后应立即清除。

在阿里云验证码控制台新建的场景不能直接写入本软件来替换杭电页面的场景。杭电的页面和服务端验签由学校维护；自建场景只有在你同时控制业务前端和后端时才可接入。若要测试自建场景，需要单独的 Web/H5 页面、概览页的 `prefix`，以及服务端把 `captchaVerifyParam` 原样提交给阿里云校验接口；不要把 AccessKey 或 Secret 放进浏览器、配置文件或仓库。

项目内的 `tools/aliyun_captcha_test.html` 和 `tools/aliyun_captcha_server.py` 用于验证自建场景。先为 RAM 子账号授予验证码权限，再在 PowerShell 中设置 `ALIBABA_CLOUD_ACCESS_KEY_ID`、`ALIBABA_CLOUD_ACCESS_KEY_SECRET`（可选的临时凭据使用 `ALIBABA_CLOUD_SECURITY_TOKEN`），运行 `.\.venv\Scripts\python.exe tools/aliyun_captcha_server.py`，然后打开 `http://127.0.0.1:8765/tools/aliyun_captcha_test.html`。页面会使用测试场景弹出真实二次挑战，服务端把参数原样提交给 `VerifyIntelligentCaptcha`；不要把这些凭据写进 HTML、配置文件或仓库。

为减少不必要的验证，保留本人账号对应的 `browser_profile/` 登录会话，并保持「启动时准备签到页」开启（`auto_sign.prewarm_browser: true`），同一次监控会复用浏览器。每次输入签到码前会检查当前页面、登录态和数字键盘是否仍就绪；检查失败会直接报告本次未提交，不会用新浏览器重试。使用稳定、正常可访问学校服务的网络，避免频繁切换代理或重复刷新、登录；登录表单自动填写尝试后会留给本人处理，不会因验证尚未完成而反复填写。以上措施减少会话中断和重复请求，不能保证平台不再要求验证。

重新登录前只会清理当前账号目录中确认已经过期的浏览器锁；如果检测到该账号仍有浏览器进程使用目录，软件会保留锁并提示先关闭对应浏览器，避免误杀其他会话。

## 识别与通知

- 「设置」页的识别设置支持每行一个关键词，也支持以 `re:` 开头的正则表达式。语义辅助识别默认关闭，可按需要开启；它在本机运行，发行包已包含模型。
- ASR 热词默认关闭。在 `config.yaml` 中设置 `asr.hotwords` 可试用；热词也可能改错数字或增加误报，建议先用自己的课堂录音核对。清空该列表即可关闭。
- 企业微信 Webhook 可留空。填写名称和地址后点击“测试推送并保存机器人”，成功才保存；测试会发送真实消息。账号可设默认机器人，每门预约单独绑定，时间不重叠时可复用，冲突时选择其他机器人。默认值变化不改已有预约，详见[通知](notifications.md)和[每课机器人](reservation-webhooks.md)。
- 「保存」或 `Ctrl+S` 保存设置。运行期间修改识别、通知等设置，需要重新启动监控后生效。

## 升级

关闭旧版，将新版解压到新目录。旧版设置与登录态包括 `config.yaml`、`secrets_local.json`、`session_local.json`、`browser_profile/`、`live_session.json`、`live_profile/`；新版还应保留 `accounts.json`、`webhooks.json` 与整个 `account_data/`。不要覆盖新版程序、运行库或模型。DPAPI 加密与当前 Windows 用户绑定，跨电脑或用户迁移可能需要重新登录与配置机器人。旧版根目录轨迹库可保留，各账号的新样本分别保存。

## 常见问题

| 情况 | 处理 |
| --- | --- |
| 无法启动，或提示文件缺失 | 重新完整解压 Windows ZIP；不要从压缩包内运行，也不要只复制 exe。 |
| 命令行电脑声音没有转写 | 确认课程有声音，并从当前默认输出设备播放；切换设备后重启命令行监控。 |
| 后台音频没有转写 | 确认课程正在直播，点击「登录并读取课程」刷新登录；查看活动记录中的直播状态或格式提示。 |
| 网页播放卡顿、占用高 | 使用「后台音频」，登录后关闭播放网页；桌面界面不支持其他直播格式。 |
| 识别程序 CPU 占用高 | 将 `config.yaml` 中的 `asr.num_threads` 设为 `1`，并重启应用。新配置默认使用单线程，保留原识别模型与 0.25 秒音频块。 |
| 登录过期或签到结果未知 | 重新登录，并在「上课啦」核对结果。 |
| 无法保存 | 将软件放到当前用户可写的目录，例如 `D:\Apps\HDUSign`。 |

## 本地数据

配置、账号、登录态和记录保存在软件目录及 `account_data/<账号摘要>/` 中。新版密码和机器人链接由 Windows DPAPI 加密，当前 Windows 用户仍可解密；旧版文件与直播／浏览器会话仍可能包含敏感资料，请勿公开分享整个目录。

转写与语义识别在本机完成；直播取流、登录、签到和企业微信通知需要联网。界面的“清空”只清理显示，不删除磁盘记录。诊断默认开启，每次监听最多保存三分钟启动音频，日志不会自动清理；可在设置中关闭诊断或打开本账号日志目录，详细内容见[诊断说明](diagnostics.md)。

## 界面与响应

桌面使用 Qt Quick。右上角可聚焦正文、展开活动记录或切换主题；设置保存使用 `Ctrl+S`，深浅主题切换使用 `Ctrl+Shift+L`。转写可以拖选复制，签到码保留前导零。活动记录仅展示最近 20 条签到事件及 1500 条日志，磁盘记录不受显示条数限制。

遇到图形驱动兼容问题时，可先更新驱动。源码诊断可设置 `QT_QUICK_BACKEND=software` 后启动；软件渲染主要用于兼容性排查，性能可能下降。退出时软件会请求后台任务停止，并等待当前网络调用结束；课程预约需要软件持续运行。
