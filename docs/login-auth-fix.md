# 登录凭据验证与浏览器认证框

未登录时，学校 `/jy-application-resourcemanage/v1/currentuser` 接口会返回 HTTP 401，
并带有 `WWW-Authenticate: Basic realm="Realm"`。
旧检测代码在页面中执行 fetch，即使还在登录页也会请求该接口，可能触发 Chromium 的原生认证窗口。

本次调整：

- 登录页或没有 JWT 登录凭据时，只等待正常网页登录，不请求当前用户接口。
- 页面脚本仅从当前可信来源读取 sessionStorage，不执行网络请求。
- 取得登录凭据后，通过同一浏览器上下文的 APIRequestContext 在后台验证账号。
- 验证请求不跟随重定向，不把 JWT 发送到其他来源。
- HTTP 401/403 或业务状态 401 时，提示重新登录；本次登录流程内不再重复验证同一失效凭据。
- 新登录凭据出现后继续验证。网络暂时失败时使用 2、4、8、15 秒的退避等待，仍可在登录时限内恢复。
- 验证成功后重新检查页面来源和 JWT；读取 Cookie 后再复查，避免切换账号期间混存凭据。
- 用户姓名和学号由后台已验证的接口返回，页面文本不作为身份凭据。取消、失败或超时不会覆盖旧登录资料。

已有预约、每课机器人绑定和默认开启的诊断模式保持原逻辑。
本修复不自动填写浏览器 HTTP 认证框、不提交额外签到，也不改变学校端的权限检查。

验证覆盖未登录不请求、401 不重复、取得新凭据后恢复、重定向不跟随、验证及 Cookie 获取期间取消/换号、暂时失败恢复。
离线验证不等于已完成真实账号登录回归，也不能保证学校页面自身不触发认证框。
