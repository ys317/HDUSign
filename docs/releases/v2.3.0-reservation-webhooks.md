# 每门课程绑定机器人（v2.3.0）

预约保存的 `reservation_webhooks` 按课程 URL 记录机器人名称、端点指纹和 Windows DPAPI 加密的链接。
预约和机器人一起写入账号配置；写入失败不会创建预约或占用机器人。

所有账号的未结束预约和正在监听的任务共用占用表，不按上课时间是否重叠区分。
机器人从预约成功起被占用，取消预约或监听结束后才释放。已绑定预约需要先取消后重新预约才能更换。
课程到点启动时，占用从预约交给监听任务，停止按钮按下后仍等待进程及其推送线程结束才释放。

当前账号选择的机器人只作为新增预约的默认值。更改账号或共用默认机器人不改变已有预约，也不改变正在运行的推送目标。
同一实际企业微信机器人即使链接参数顺序不同、附带其他参数或名称不同，也按同一个机器人判断。

冲突时弹窗显示占用的账号、课程、时间；选项仅包含已保存且测试成功的空闲机器人。
点击确认时重新检查占用。没有空闲机器人时，提示添加并测试机器人，或者取消本次预约操作。
取消弹窗不新增预约；既有“待选择机器人”的预约仍保留，可以从预约列表点击“选择机器人”处理。

旧预约启动新版后迁移：原机器人空闲时，固定保存到该门课；冲突、损坏或解密失败时标记“待选择机器人”。
未处理的旧预约到点仍可本地监听、识别和保留记录，但不向账号默认机器人发送通知。
监听中人工选择空闲机器人后，新的提醒才开始推送；不会补发之前的记录。
原先没有配置机器人的预约继续仅本地提醒，可在列表中选择机器人。

每个监听任务拥有独立且加密的 `notification_routes/<随机标识>.json`。
工作进程只接受当前账号目录、正确任务标识的路由；文件缺失或损坏时关闭推送，绝不退回账号默认链接。
停止后删除该任务的路由文件。提醒、签到码、签到结果仍由同一个课程任务推送，保留姓名和课程名。

离线验证包括：跨账号及同账号冲突、不重叠预约占用、过期和取消释放、推送结束前不释放、旧预约迁移、重启恢复、默认值变化、确认时再次检查、写入失败回滚、相同机器人别名、真实 QML 弹窗和模拟 HTTP 请求目标。
贡献分支记载过冻结程序的检查；本次合并没有重新构建或核验这些历史产物。
测试不会连接学校或向真实机器人推送。
