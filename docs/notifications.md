# 企业微信推送 v2.0.6

> 版本范围：本文记录 v2.0.6 的通知身份。当前通知使用实际预约／运行任务的课程快照，机器人按课程独占绑定；后续行为见[每课机器人](reservation-webhooks.md)和[功能规则](功能规则.md)，下文“没有更改机器人地址”仅指当次版本变化。v2.3.2 已交付移除自动签到，下面提到的签到结果和人工验证通知仅属于旧版；当前仅保留识别提醒和签到码通知。

从课程列表选课并启动监听后，签到提醒、签到码、自动签到结果和人工验证通知
都会带“姓名”和“课程”。姓名来自学校 /v1/currentuser 返回的 userName；
课程使用本次选中的课名，三节课切换链接不改变课名。

登录时仅从已经验证成功的当前用户响应保存姓名和学号标识。
旧登录资料没有姓名时，启动监听会用同一个登录态补查一次，只读请求。
账号标识不匹配、登录失效或读取失败时不使用其他账号的姓名，并显示未获取提示。
未从课表选择的手动网址显示未选择课程，避免猜错名称。
“测试推送”同样携带当前填写的账号和所选课程信息。
姓名和课程仅绑定本次任务，后续修改界面不会改变正在处理的通知所属课程。

没有更改机器人地址、推送级别和签到逻辑。旧版课前/课后两分钟以及六秒重试保留。
