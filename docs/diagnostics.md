# 启动音频诊断（v2.2.1 默认开启）

新账号默认开启。现有账号首次使用 v2.2.1 时也会开启一次，并保存迁移标记。
之后在“设置 → 诊断与日志”关闭“启用启动音频诊断”并保存，重启后仍保持关闭。
该开关按账号保存，从下一次启动监听生效；之后修改一个账号不影响其他账号。
仍保留每节课前两分钟尝试连接、未开播六秒重试及整堂课结束后两分钟停止的规则。

## 保存内容

无论是否开启诊断，完整监听输出都会保存在对应账号的：

`account_data/<账号目录>/logs/<日期_时间_随机后缀>/`

在设置中点击“打开本账号日志目录”可以直接找到。每次监听独立一个文件夹，
退出或停止监听后保留；不会自动清理这些日志。

- `console.log`：完整运行输出，包括启动、重连、草稿、完整转写和签到提示。
- `events.jsonl`：带北京时间毫秒时间戳的结构化事件，包含任务发起、模型加载、
  首次收到解码音频、首次出字、首次完整句子；开启诊断时增加完整草稿和指标。
- `summary.json` / `诊断摘要.txt`：停止后生成的时间线、识别耗时和录音信息。
- `startup-audio.wav`：仅开启诊断时生成，16 kHz 单声道 16-bit PCM，可直接播放。

有课表时采样窗口为本次对应节次正式上课前 2 分钟至上课后 1 分钟。
例如 18:30 开课，窗口为 18:28–18:31；开启晚了只能保存窗口里实际收到的部分。
已错过该窗口而中途启动，或没有可靠课表时间时，保存本次启动后的前三分钟。
每次监听最多保存 180 秒音频，约 5.8 MB，不会录制整堂课。

录音就是本机当时交给识别器的解码音频，不是学校端的原始录音。
断流缺口不会被补成静音；已收到的片段会拼接到 WAV，原来的时间、
样本偏移和课程编号在 `recording_segment` 事件和 summary.json 中标注。
在一个连堂监控任务中仅保存这一段启动诊断窗口，不会每节另录三分钟。
录音保存失败时继续监听，事件和摘要会标注失败。

## 判断方法

1. 对照“任务发起”“模型准备完成”“首次收到解码音频”，判断准备或连接耗时。
2. 对照“首次识别出文字”和“首次完整转写”，判断是识别晚出字还是等停顿断句。
3. 播放对应时间的 WAV，确认电脑实际收到的音频里是否已经有老师讲话。
4. 查看 `audio_metrics`：约每 5 秒一条，含该段 RMS/峰值音量、低音量样本比例、
   累计识别音频秒数、累计识别调用耗时、最长单次识别耗时，以及跳过的积压音频。

`asr_processing_rtf` 是识别耗时除以已处理音频时长；大于 1 说明识别处理跟不上。
它不是网络延迟。低音量也不等于没有人声，不能只靠音量就断定老师没有讲话。
如果 WAV 早有人声但没有草稿，优先排查输入声道、音量和模型；如果草稿早已
出现但完整句子较晚，优先核对断句。程序没有据这些指标自动修改识别参数。

诊断新增的结构化字段不采集账号密码、Cookie、JWT、WebHook 链接或完整媒体地址，
也不复制配置和登录文件。账号、课程名、课堂文字和已识别签到码仍会出现在本机
日志中。可在设置中关闭诊断音频保存。
突然强制结束进程时，已经写出的 console/events/WAV 尽量保留，最终摘要可能尚未生成。

## 验证范围

离线测试覆盖三分钟边界、静音/有声样本、草稿早于完整句、断流缺口、切换课程、
录音关闭、录音写入失败、进程退出后保留日志，以及五个进程各写各的不同音频样本。
这些检查不连接学校、不签到、不向真实机器人推送；不能恢复以前没保存的音频。
