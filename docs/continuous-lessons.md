# 连堂课与自动续接

列表选择的两节、三节连堂课，每一节都提前 2 分钟尝试监听；第三节提前切换，
最后一节下课后 2 分钟停止。预约倒计时显示距离监听启动的时间。
平台尚未开播时每 6 秒重试，最多等到正式上课后 2 分钟；用户可随时停止。
提前尝试不保证平台已有音频，加载浏览器和模型仍需耗时。
仅手填 URL 且未匹配课表的课程没有可靠课表时间，仍沿用平台提供的直播时间。

## 使用

1. 登录并刷新今明课程，在课程列表选择一堂课。
   软件同时读取“我的课表”，补回直播列表可能已隐藏的早先节次，避免中途
   启动时将三节误判成两节。完整课表不可用或资料矛盾时保留单节模式并提示。
2. 同一天、同教学班/科目/教室/学期、节次相邻、每节 45 分钟且课间不超过
   20 分钟的两节或三节课，会合并为一堂，显示完整起止时间和“2节/3节连堂”。
3. 两节课全程使用首节 ID。三节课在第三节正式上课前 2 分钟切到首节 ID + 2，
   同时重新获取该 ID 的媒体地址与取流令牌。第三节 ID 必须已出现在课程列表中。
4. 中途启动会按课表时间选择第一段或第三节。预约恢复后同样保留整堂课信息。
5. 直播正常时课间持续监听；已知课间断流会等待到下一节课前 2 分钟恢复尝试。
   第二节仍使用首节 ID；未开播每 6 秒重试，最多等待到该节正式上课后 2 分钟。
   等待期间可以随时停止；整堂课最后一节结束后 2 分钟停止。
   切换前关闭旧音频连接并清除未完成转写，已确认的签到码保留。

只有从列表选择、成功识别为两节或三节连堂的课程启用此逻辑。手动填写网址、
元数据不完整、ID 不连续、四节以上等情况保留单节行为，不猜测下一节。
切换按电脑时间与课表时间执行，请保持系统时间准确；睡眠期间不能采集音频。

## 验证与构建

离线测试覆盖两／三节分组、课间与跨天隔离、编号校验、中途启动、精确切换、旧连接清理、识别缓存重置、课间等待及取消。前两节复用首节播放 ID、第三节切换的规则仍需在实际课堂核对；不完整元数据不会推算链接。

常规源码运行和完整发行包构建见[开发指南](development.md)。`tools/build_continuous.py` 保留贡献分支的增量归档构建方式，要求核验过的 v2.0 基础 EXE、对应依赖和 Python 3.13.7，并按源码位于便携目录下一级的布局运行；普通仓库使用 `tools/release.py`。增量构建不会替换旧产物，也不代表已经发布本次合并版本。
