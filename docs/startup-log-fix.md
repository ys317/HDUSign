# v2.1.1 启动日志实时刷新

修复多账号子进程启动日志被缓冲，直到出现第一段识别文字才集中显示的问题。
原界面给日志标注的是收到日志的时间，因此这种缓冲会误导用户以为刚刚才启动。
现在在程序入口显式启用行缓冲与直接写入，不再只依赖 PYTHONUNBUFFERED 环境变量。

实际排查：2026-10-15 的监听进程于 17:58:00 启动，当前 FFmpeg 进程于
17:58:18 启动，但启动日志统一显示在 18:00:50。原始输出的首段非空识别是
“五九九五五九九五”；18:00:52 从稳定的部分识别提前提取签到码，
18:00:53 才输出完整转写。更早是否有人讲话、有没有未识别的语音，没有原始
录音可验证，不能据此断言全程零漏识别。

验证用实际打包 exe 启动一个无 ASR、无学校请求、无推送的离线账号子进程，
让子进程保持运行，检查启动日志在它退出前已经到达主进程。
当前上课中的旧版进程没有被停止；请下课后切换到新版。
