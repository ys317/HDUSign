# HDUSign 本地定制版

面向杭电智慧课堂的 Windows 课堂辅助工具：后台直播音频、本地语音转写、签到提示与口播码识别、预约监听和可选企业微信通知。源码基于上游 [ys317/EchoSign](https://github.com/ys317/EchoSign) v2.0，本地已包含后续定制功能，不能视为与官方版本完全相同。

当前源码及最新交付版本为 **2.3.3**（2026-10-28）：账号任务按预约优先、组内最近使用排序，预约账号底色加深；新增可关闭和调节的桌面透视玻璃外观。运行 **`HDUSign-v2.3.3-预约排序与玻璃界面.exe`**，旧版 EXE 保留供回退。

## 启动和更新

支持 Windows 10 / 11 x64。便携运行目录是 本目录的上一级（`../`），源码仓库是 本目录。

1. 退出旧版程序，避免同一账号资料被多个版本同时使用。
2. 在便携运行目录启动 **`HDUSign-v2.3.3-预约排序与玻璃界面.exe`**。
3. 保留同目录的 `_internal/` 和 `models/`，以及个人资料。不能仅复制 EXE 到空目录运行；不要在压缩包中直接启动。
4. 新版文件名采用 `HDUSign-v版本号-更新内容.exe`，构建脚本已适配；旧文件不更名。版本号第一位升级必须先说明并取得用户明确同意。

原 `HDUSign.exe` 是 v2.0 基线，不是最新定制版。GitHub 上游下载也不包含这里全部定制功能。使用旧 EXE 不保证兼容新版账号和预约格式。

## 登录、选课和预约

在设置中选择已保存账号或新建账号，填写学号密码后发起登录，必要时在浏览器完成操作。成功且选择记住后保存加密密码，失败不覆盖已保存资料。账号可修改或删除；删除会清理对应登录状态，运行中的账号须先停止。

用户要求仅自动填入、由本人点击登录，但当前 SSO 辅助仍会尝试自动提交，这是已记录的待修正项；不要将当前程序理解为已经完全符合该要求。

各账号分别读取课程、选课和预约，最多同时监听五个账号。每账号可预约多门不重叠课程，依次运行；点击其他课程只切换查看，不取消预约。预约列表可逐门查看和取消，切换账号显示不会停止其他账号。预约需要保持软件运行，关闭或睡眠期间不能监听。

左侧账号任务优先显示已有预约的账号，两组内部各按最近使用时间降序排列；预约账号底色略深，选中账号另有边框。切换账号、成功登录、成功预约或开始监听后更新使用记录，已保存账号重启后保留；后台刷新不改顺序，无历史记录的旧账号保留原相对顺序。

符合元数据条件的两节／三节连堂合并为同一堂课，每节提前两分钟尝试，整堂课末节下课后两分钟停止；第三节也提前两分钟切到首节 ID 加二，未开播时每六秒重试。正常收音时课间持续监听。手填网址、课表不完整等场景的边界见[功能规则](docs/功能规则.md)。

## 全局玻璃外观

在“设置”页底部的“全局玻璃外观”中开关桌面透视，调节背景透视程度、玻璃着色浓度和液态边缘高光，点击“保存全局外观”后对所有账号和重启生效。设置单独保存在 `appearance.json`。

桌面透视需要 Windows 11 22H2 及以上；不可用时使用普通外观。系统负责模糊，滑块调节透视、着色及高光，不提供精确模糊半径或透镜折射。详见[玻璃外观与验证](docs/appearance.md)。旧版 EXE 不包含此功能，更新前先退出旧版。

## 微信机器人

在设置中给 Webhook 命名，点击测试；只有测试成功才保存。测试会实际向该机器人发送消息。账号可配置自身默认或使用共用默认，通知带经过验证的姓名和任务课程名。

v2.3.2 按课程开始前 2 分钟至结束后 2 分钟比较机器人占用；时间不重叠（包括边界恰好相接）的课程可复用同一个机器人，跨账号也一样。连堂课包含课间。冲突时人工选择其他已测试且时间不冲突的机器人，已有绑定不随默认值改变。缺少可靠时间，或旧任务仍在结束、超时未退出时，不推定可复用。v2.3.1 EXE 仍使用预约全程独占的旧规则。

旧预约冲突等情况会标记“待选择机器人”；未处理时仍可本地监听，但暂停微信通知。详情见[每门课程绑定机器人](docs/reservation-webhooks.md)。

## 日志和诊断

诊断默认开启，按账号保存；旧账号升级时开启一次，之后手动关闭可保持关闭，下次监听生效。设置中可打开本账号日志目录。每次监听保留 `console.log`、`events.jsonl` 及结束摘要；开启诊断时还保存最多三分钟启动音频，不是整堂课录音，日志不会自动清理。

首条完整转写时间不等于首次收音时间，签到码也可能由稳定草稿提前确认。遇到出字晚，先对照结构化事件和实际录音，参见[诊断说明](docs/diagnostics.md)。

## 当前验证范围与限制

- v2.3.3 当前 Qt／核心回归 402 项（397 通过、5 跳过）；冻结 EXE 原生桌面透视、滑块、深浅主题、外观保存及标题栏按钮离线检查通过。旧 Tk 测试环境限制仍存在，没有真实课堂或真实机器人投递验收。
- v2.3.2 源码回归 388 项（383 通过、5 跳过）；新 EXE 的界面、模型、音频解码、登录检测和五进程通知路由离线检查通过。旧版程序、旧版界面资源与个人配置／会话的 59 个文件校验保持不变；未进行真实课堂或真实微信投递验收。
- v2.3.1 已修复程序页面探测可能触发原生认证框的问题，离线及匿名浏览器检查通过；尚未完成用户已保存账号的真实登录回归，也不能保证学校页面自身不弹框。见[登录验证修复](docs/login-auth-fix.md)。
- 多账号隔离有五进程离线与冻结程序路由检查；两个账号同时接收真实课堂音频、不串流的完整验收仍待进行。
- 当前源码不打开签到页、不输入签到码、不提交签到；识别后仅提醒并向绑定的微信机器人推送，签到由本人在平台完成。直播登录仍可能需要人工验证。如回退到旧 v2.3.1 EXE，其自动签到行为仍然存在。
- 没有显式新增人声增强、降噪或说话人分离。不能仅据第一条文字断言此前没有人声或没有漏识别。

## 个人资料与升级保留

保留整个便携运行目录最便于原机继续使用。若移动到新目录，至少核对根目录配置、`accounts.json`、`webhooks.json` 和整个 `account_data/`；旧版遗留的会话／配置也不要在未核对迁移前删除。程序、依赖和模型使用匹配版本，不要直接覆盖个人数据。

密码和机器人链接由当前 Windows 用户的 DPAPI 加密，跨电脑或 Windows 用户不能保证解密；直播会话和浏览器资料仍包含敏感登录凭据。日志／诊断录音也含课堂文字、姓名或签到码。请勿分享使用过的完整目录，反馈问题时遮盖个人信息和凭据。
